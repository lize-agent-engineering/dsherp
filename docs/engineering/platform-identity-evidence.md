# 平台身份与真实只读入口验收（阶段 3 部分）

日期：2026-08-28。独立平台 Site 拓扑经用户确认；以下仅为本地隔离合成环境，不代表生产部署或完整阶段 3。

## 已实现

- 平台 Site `dsherp-platform.localhost` 安装 Frappe 与 `dsherp_platform`，不安装 ERPNext；原生设置向导通过原生 `setup_complete` 方法完成，不直接修改完成标志。
- alpha 为既有业务 Site，beta 为新增独立 ERPNext Site。三者独立站点卷、数据库和数据库用户；共享验证环境 MariaDB/Redis 进程，不能据此宣称任意 Agent 代码已隔离。
- 原生平台登录，Enterprise / Membership 使用自定义 DocType；成员关系明确绑定业务用户，不按同邮箱推断。普通成员看不到 API 密钥；平台管理员没有隐式业务权限。
- 业务读取先校验平台会话、成员启用、企业状态、固定服务端地址与业务用户身份，再使用该成员专用凭证调用业务 Site。业务权限仍由业务 Site 执行。
- 禁止修改已存在成员关系的企业和平台用户；需要停用旧关系后新建。请求中身份校验后结束只读事务快照，再复核最新成员关系，防止旧快照隐藏撤销。
- React + Ant Design 真实入口 `/app/dsherp-home`，显示登录账号、已加入企业、真实字段与记录；企业切换清空旧结果并取消旧请求。无演示角色切换。

## 真实 UI

平台入口使用 `http://platform.localhost:18083/app/dsherp-home`。必须使用独立 hostname：端口不能隔离 Cookie，平台代理拒绝其他 Host。

通过原生登录表单登录合成普通成员，甲企业 `DSHERP-TEST-ITEM` 查询回读成功，切换乙企业清空旧编号和记录；在页面选择乙企业，输入 `DSHERP-BETA-ITEM` 并查询，实际表格返回 `乙企业专属合成物料`、乙企业物料组与单位。首次页面失败定位为未完成原生初始化；已通过原生初始化解决。实时通信 Origin 参数曾未被镜像脚本替换，已用本项目代理启动脚本修正，不修改上游文件。

## 验证口径

- 串行整套 Python 回归 55 项通过（57.58 秒）。前端 25 项测试通过；Ant Design 5.27.6 lint 无问题，构建成功。
- 身份集成覆盖：原生登录、成员列表、两企业数据、越权对象/记录/字段、成员撤销、绑定身份不匹配、原生页面权限、禁止编辑成员标识、Cookie hostname、实时通信 Origin。
- 并发撤销测试使用真实 MariaDB 两个独立事务，HTTP 身份调用用同步替身，不能冒充全链路真实 HTTP 并发验收。去掉新快照操作时按预期失败；恢复实现后通过。
- 曾并行执行两个修改同一合成成员的测试，造成一次整套测试失败；最终验收以串行整套重跑为准，不将该失败藏为通过。

## 资源与重现

11 个项目容器配置上限合计 4096 MiB、2 CPU。检查时全部运行、无 OOM、重启计数为 0；该结果不是压力测试。MariaDB 数据目录总计 445 MiB，新站点卷与日志各不足 1 MiB，低于已授权新增数据上限；未拉取新镜像，未修改其他项目服务。

首次建站使用 `infra/provision_identity.py`，控制凭证仅挂入短时开通容器；随后 `run_identity_seed.py` 建合成普通用户，`bind_identity.py` 建显式绑定，`setup_platform.py` 完成原生平台初始化。脚本对已有站点/绑定拒绝覆盖，不能在未知部分成功状态盲目重跑。凭证与管理员密码只存忽略的 `.runtime/`，不入 Git。
