## 隔离环境方案（待资源授权）

建议使用现有官方 ERPNext 镜像的固定 digest，不共享现有容器或数据；独立 compose project `dsherp-validation`，专用网络、MariaDB/Redis 和卷。先验证镜像内实际 Frappe 版本，再决定是否满足基线。初始资源预算最多 4 GiB 内存、2 CPU、10 GiB 新数据空间；站点 HTTP 仅绑定 `127.0.0.1:18081`（盘点时未占用，启动前须重查），数据库和 Redis 不映射宿主端口。

本机当前已有 23 个运行容器且 swap 使用约 3.83 GiB，不能保证新增 ERP 栈不影响现有服务，因此需要用户授权此资源占用，或提供另一台隔离测试环境。不得通过停止现有服务腾资源。

## 验证前所需条件

- 明确授权新建隔离站点（建议 `dsherp-validation.localhost`），或提供已确认仅用于合成测试的专用站点 URL。
- 独立开通管理凭证只用于控制面建站/创建合成数据，不进入 Agent。
- 普通测试用户具有 Customer/Item read 权限；另一无权限测试用户用于拒绝验证；两个用户都不是 Administrator。
- 仅生成 `DSHERP-TEST-*` 合成客户/物料；从真实站点发现可用字段、必填值和 Link 选项后创建，不能从文档猜字段。
