# Agent 界面重构记录

对象：业务页面 Agent 侧边栏（`ContextSidebar`）与正式 Agent 工作台（`AgentWorkbench`）。只改前端结构、样式与对应测试，没有改动会话、运行、HITL、配置执行的后端与接口语义。

## 视觉基座

新增 `frontend/src/agent-theme.css`，两个界面共用同一套 token 与原语：冷灰画布、单一绿色强调、层级化阴影、固定字号级差、统一动效（120/180/220ms，`cubic-bezier(.22,.61,.36,1)`）。原来分散在 `ContextSidebar.css` 与 `ContextSidebarEnhancements.css` 的重复职责已合并，`ContextSidebarEnhancements.css` 删除。CSS 恢复为多行可维护写法。

原来的 `.dsh-workbench * { transition-duration: 180ms }` 全局选择器已删除；`prefers-reduced-motion` 仍统一关闭动画、过渡与平滑滚动。

文字对比度（自测，WCAG AA 需 4.5:1）：正文 17.19、次级 9.02、弱化文字在白/画布/栏底/凹陷背景上分别为 5.23 / 4.77 / 4.99 / 4.63，强调色 5.26，成功 5.63、警告 5.23、危险 5.58、中性 5.04。占位符文字从 Ant Design 默认的低对比灰改为弱化色 token。

图标改用 `@ant-design/icons`（原来是 `☰ ＋ × ⌁ ▤ ↑` 等字符），品牌星标改为自绘 SVG。所有装饰性图标加 `aria-hidden`，图标按钮保留显式 `aria-label`。

## 状态词汇

新增 `frontend/src/agent-format.js`（含独立单元测试）：把 `Pending / Authorized / Succeeded / Partial / Unknown / Failed / Draft` 等翻译成中文说明，同时**始终在旁边显示服务端原始状态字符串**。未知状态原样透出，不吞掉也不归类成成功。过期时间单独显示，`Pending` 不会被改写成 `Expired`。

## 侧边栏

- 上下文从占固定纵向空间的卡片改成头部下的细条，长对话里不再挤占时间线。
- 时间线从"流程日志"竖线改成对话结构：用户消息右对齐气泡，模型回答全宽正文，来源上下文降级为安静的元信息行。
- 运行阶段来自真实运行状态（`Queued / Running / Cancelling`），没有编造"读取 ERP、调用模型"之类的假步骤——接口目前不提供更细的阶段。
- 回答接入 `remark-gfm`：Markdown 表格真正渲染成表格，并在自己的横向滚动容器内，不再撑开抽屉。超长回答折叠并可展开；折叠只作用于回答正文，错误、提案、执行结果始终可见。
- 操作与配置提案包在独立确认卡里，与正文分层。
- 抽屉宽度改为 `clamp(340px, 34vw, 520px)`，≤560px 视口全宽。

## 工作台

- 删除页面内重复的"Agent 工作台"标题（Frappe Page 已有标题）。四个一级视图与操作合并进同一条 52px 命令栏，少占一整行。
- 会话列表从整行 `Button` 改成信息分层的列表项：标题两行截断、相对时间、归档标记、选中态用底色而非强对比主色。加载有骨架屏。
- 待确认／执行记录／应用配置改成真正的主从详情：左列表带类型、状态、时间、有效期，右详情按需 `get_session` 后在**记录所属会话中精确定位那一条**提案／执行／配置包并原地展开，不再把用户丢回长对话顶部。仍提供"在对话中打开所属会话"并高亮对应锚点。
- 记录在所属会话中找不到时如实说明（可能权限、成员绑定或版本变化），不据列表推测结果。
- 右侧上下文栏补足信息密度：当前对象、来源路由、对象版本、已授权字段、会话状态、对话轮数、待确认数；桌面端可收起。业务正文不进 URL。
- 会话与记录列表取消翻页，改为向下渐次加载：`IntersectionObserver` 到底自动取下一页并追加，已加载的会话不会被丢弃；同时保留可见可聚焦的「加载更多」按钮，供键盘用户与没有 `IntersectionObserver` 的浏览器使用。`search_sessions` / `list_*` 的 `page` 语义未变。
- 重命名改为就地更新列表项，不再整表重载回第一页。
- 输入区补齐与侧边栏一致的文本附件能力（TXT / Markdown / CSV / JSON，6KB 上限，与问题合计 8000 字符），附件内容仍标注为数据而非系统指令。这是原来两个界面唯一的功能不一致处。
- 发送增加单次提交守卫，避免一次点击产生两个运行；记录详情增加请求票据，迟到响应不会覆盖新选择。
- 布局高度改为实测 Frappe navbar 与 page head 的实际偏移，不再依赖硬编码的 106px。

## 窄屏抽屉关闭失败的根因

Frappe desk 的 navbar 用 Bootstrap 的 `.sticky-top`（`z-index:1020`）/ `.fixed-top`（`z-index:1030`）；Ant Design Drawer 默认 `z-index:1000`，因此 navbar 图层压在抽屉顶部，右上角关闭按钮收不到点击。修复：工作台两个抽屉显式 `zIndex={1080}` 并配 `.dsh-wb-drawer{z-index:1080}`，另提供带明确中文 `aria-label` 的自有关闭按钮（Ant Design 默认关闭按钮的可访问名是英文 "Close"）。侧边栏抽屉一并提升到 1040。

## 作用域措辞

原措辞（侧边栏「当前页面」、空态「我会结合你当前打开的业务页面回答」、工作台「本次请求会带上的范围」）容易被读成"只能问当前这一页"，与实际行为不符：读工具 `erp_search_records` / `erp_read_record` 不以页面上下文为过滤条件，真正的边界是 DocType 白名单（Item / Customer / Sales Order）、当前业务用户的 ERP 权限、以及本次消息选择的任务领域。页面上下文是来源证据，服务端还会用实际已保存值覆盖客户端传来的 `server_version`。唯一真正绑页面的是 `erp_propose_fill`，浏览器端在应用前比对路由、表单与版本。

据此只改文案、不动逻辑：

- 侧边栏细条：`当前页面` → `提问起点`。
- 侧边栏空态：改为"以当前页面为起点，也能查你有权限的其他物料、客户和销售订单。任何写入都会先请你确认。"
- 侧边栏建议提示：`按当前对象查询关联单据` → `不限当前页面，按你的权限检索`。
- 工作台上下文栏标题：`当前上下文` → `本次来源`；脚注改为"这些是本次请求会带上的来源信息，不是查询范围：Agent 可以检索你有权限的物料、客户和销售订单。发送时服务端仍会复核身份、权限、对象版本与已保存事实。"
- 工作台对话空态：改为"工作台不绑定具体页面，可直接检索你有权限的物料、客户和销售订单。想让 Agent 带上某条记录的当前状态，就在那个业务页面右下角打开 Agent。"

# 第二轮：以对话为主体的重构

第一轮把四个一级视图做成了平级标签，用户反馈"太乱、信息太平铺"，并明确要求参考 Codex / Claude Code 桌面版：待确认应绑定在会话里、执行的工具按发生位置显示在对话中、归档独立成设置页。本节记录这一轮。

## DSH 侧的既有设计

`deepseek_harness` SDK 的 `RunResult` 把一次运行建模为 `events: [{type, data}]`，并提供 `final_response(events)` / `finish_reason(events)`，事件类型形如 `assistant/message`、`turn/end` —— 与 Claude Code / Codex 渲染的事件流同构。

但本项目的 runner（`dsherp/context_runner.py`）只保留 `final_response` 与 `finish_reason`，**丢弃 `result.events`**，没有任何地方持久化 DSH 事件流。真正被持久化的是 `DS Model Run.sources`：服务端在 `run_tool` 里逐条记录并逐次重新授权的 ERP 读取（工具名、参数、读到的字段与记录、版本）。

因此对话里显示的"工具调用"取自 `sources`，是服务端已授权的真实读取，而不是模型自述的步骤。**代价要说清楚**：`sources` 不含逐条时间戳，只有追加顺序，所以能还原"在这一轮的第几步"，但还原不了每次调用的墙钟时间；要精确到时间需要在写入 `sources` 时加时间戳，那是一次后端写入路径的改动，本轮没有做。

## 后端改动（只在已授权的读取序列化里补字段）

| 位置 | 改动 | 为什么安全 |
| --- | --- | --- |
| `context_api._public` | 每条消息补 `sources` | 同一函数本就对这批数据调用 `authorize_sources`（逐字段、逐记录复查读权限，权限变了就抛错），暴露它没有放宽任何访问 |
| `operations.get_proposal` | 补 `model_run` | 该字段本就存在于 `DS Operation Proposal`，`execution_ready` 已在读它 |
| `configuration.get_bundle` | 补 `model_run` | 取自 payload，`_origin` 已在读它 |

没有新增接口、没有改变任何接口语义、没有改动 HITL 或配置执行路径。新增 `tests/integration/test_context_transcript.py` 覆盖：消息带回自己那一轮的工具读取、提案带回产生它的运行。

## 信息架构

- **对话是唯一主表面**：删掉一级标签栏。Frappe 页面头部已有标题，页面内不再重复。
- **待确认回到会话里**：提案／配置确认按 `model_run` 落在产生它的那条消息下（`agent-transcript.js`，纯函数 + 单测）。归属不明的条目单列在"未能归属到具体消息"，如实说明不推测。
- **工具调用内联**：每轮的 ERP 读取以安静的单行事件显示在回答之上。
- **会话栏状态点**：橙点＝有待确认（来自既有 `list_pending`），蓝点＝有本机未看过的新消息（`localStorage`，首次见到的会话不标记，避免满屏蓝点）。颜色不单独承载含义——状态同时写进按钮的可访问名。
- **新建会话**移到会话栏顶部的图标按钮。
- **执行记录**降为会话栏底部的次级入口。
- **应用配置 + 已归档对话**移入 **Agent 设置**：用 Frappe 原生 `page.add_button("Agent 设置", …, {icon:"setting-gear"})` 注册在页面头部右上角（它同时自动生成移动端菜单项）。设置内部是 Codex 式的分区导航；以后所有 Agent 配置相关内容都进这里。
- **归档**：会话栏不再有"进行中／已归档"切换，左栏只列进行中；归档列表成为设置里的独立页，可搜索、可取消归档、可直接打开（只读）。没有删除操作——后端没有删除接口，就不做出有这个能力的样子。
- 右侧上下文栏删除，事实收进对话标题行下可展开的一行。

前端新增 `agent-transcript.js`、`AgentRecords.jsx`、`AgentArchive.jsx`，`mount()` 返回的句柄带上 `openSettings`，交给原生页面头部调用。

## 两次误判，记录在此

1. 一度以为 `destroyOnHidden` 破坏了抽屉展开动画。真实原因是 Browser 面板隐藏时 `document.hidden === true`，rAF 被节流，rc-motion 的进入过渡没走完，导致读到的 transform 停在起始值。面板置前并产生真实帧后读数正常。虽然结论是"没有 bug"，仍保留了改动：设置内容改为"保持挂载 + 令牌刷新"，比每次重挂更好——不闪骨架屏，也不会让测试拿到已脱离文档的节点。
2. 记录视图"没撑满高度"同样是截图合成的缩放假象，实测详情面板底部正好落在视口底部。

## 部署注意

Frappe 把 Desk Page 的 JS 缓存在浏览器 `localStorage`（`_page:<name>`），并由 `metadata_version` 决定失效。改动 `dsherp_agent.js` 后，仅重启后端不足以让已有会话看到新页面头部按钮；需要站点缓存清理并让 `metadata_version` 变化，否则用户会继续拿到旧的页面脚本。本次验证中是手动清掉了 `_page:dsherp-agent` 才看到 Agent 设置按钮。
