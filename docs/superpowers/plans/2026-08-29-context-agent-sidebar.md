# 原生业务页面上的上下文 Agent

日期：2026-08-29。用户已确认执行；持续目标 active。当前 main 工作，不建 worktree、不推送。

## 目标与替代范围

本计划包含 Agent 执行循环、领域能力、上下文、会话、工具、人工确认及原生侧栏，不只是 UI。企业日常工作使用 Frappe/ERPNext 原生页面，全局按钮打开 React + Ant Design 右侧面板；不以 `/app/dsherp-home` 聊天页作为业务主入口，不做普通/Agent 两套模式。平台负责统一登录及企业成员关系；业务 Site 负责业务身份、权限、会话和执行记录。

本计划替代旧计划中的独立工作台、双空间导航、任意生成代码、破坏性结构修改方向。旧 Demo 保留独立入口、移出正式导航且不再扩展；其他被替代实现清理，有效回归保留。旧平台任务历史只读保留，不迁入新企业。

- 固定 SDK/Runtime 0.1.1rc1（源码 528c682e061696f5a160f363f236ecbf53cbd006）；不改上游核心，不另写 Agent 循环。SDK 未暴露的能力用项目 Cordis 插件接入，不伪称官方接口，不修改上游私有字段，不擅自升级或削减恢复/取消。
- 不修改 AgenERP/其他服务，不扫描其他项目密钥；本项目已有模型授权内使用，不能扩大生产写入或无限资源。仅缺凭证、新授权、关键架构决策询问。
- 不用定时自动化替代持续目标，全部目标实际达成才 complete。每阶段记录代码、单测、真实 Runtime、真实模型、真实 ERP、UI、部署，互不替代。

## 插件、领域与协议

1. SDK 接入插件：显式创建、原生恢复、取消、安全关闭；复用 Agent、持久化、checkpoint 和协议。仅一个 stdio 入口，评估公开 JsonRpcLineTransport/HarnessSdkJsonRpcServer，不同时抢 stdin。
2. 业务上下文插件：页面快照、来源、版本、历史、业务状态及模型输入预算。
3. 查询、业务操作、应用配置三个领域各自限定工具和 skills；复用 MCP/Frappe。业务 skills 固定版本并校验摘要，只读指定目录、includeDefaultRoots=false、watch=false。缺失/错版报错，不加载个人开发 skills，不允许模型修改权限或工具集。首版无多 Agent 并发框架。
4. 工具/HITL 适配：模型生成提案，服务端确认后执行；业务、配置、填表都要 HITL。内部会话与审计持久化不属于待确认业务写入。

## 会话与上下文不变量

- 业务 Site 分别持久化用户会话、模型运行、操作提案、执行记录。每消息绑定发送时快照；跨页继续不改变已提出操作目标。
- 原生日志按企业/用户/会话/领域隔离，稳定 session_root/cwd，每运行会话单写者。跨进程必须显式原生 resume，不以相同 ID 或保留 Python wrapper 冒充恢复；退出确认 flush/dispose。
- 刷新只恢复展示，不自动运行模型/写入；request_id 去重。多标签并发必须协调。
- 等待 HITL 结束本轮运行并释放容器；确认重新检查身份、权限、版本并用新短期执行凭据。取消停止后续工作，不撤销既有写入；结果不明先核实，不盲目重试。
- 权限、运行配置或 skills 版本变化后废弃旧运行上下文，重新授权开启新运行；旧日志仅审计，不直接重喂模型。
- 页面快照覆盖路由、类型、DocType、记录、筛选、选中项及用户允许的未保存字段/子表变化。前端只是上下文，身份/权限/已保存事实由服务端确认。不整页抓 DOM、不默认上传全单/数据库/历史。
- 输入按需包括问题、快照、领域规则、近期对话、带来源摘要、待办提案及最新工具结果。保留调用-结果关系、来源及版本；完整提案存业务数据库，不依赖摘要重建。
- 历史和摘要重新使用前复查来源权限，撤权不能只隐藏 UI。所有模型调用（包括压缩直接 ctx.llm.stream）均检查权限和预算；阻止自动压缩 WARN AND CONTINUE 的不安全继续，不静默裁掉关键业务值、批准内容或版本。
- checkpoint 证明 Agent 状态，ERP 执行记录证明业务结果，二者不能替代。

## 阶段一：原生侧栏与真实多轮查询

- 原生业务 Site 登录下先交付面板，不等待统一登录：打开/关闭、跨页继续、新会话、历史、取消，显示使用的页面/单据，未知页面说明能力有限。
- 完成插件协议、跨进程持久化恢复、上下文管理、真实模型与当前用户可读数据。不得自动保存或刷新覆盖原生未保存内容。
- 随后平台到 Desk 登录衔接，校验成员关系和业务用户映射，使用 Site 验证身份，旧平台历史只读。

## 阶段二：业务操作与 HITL

- Item/Customer 新建和修改；Sales Order 草稿创建、修改、提交、取消；当前表单建议填入，确认后应用，保存和提交分别确认。
- 流程：需求 → 具体差异与影响 → 确认 → 服务端复查 → 原生业务方法 → 回读结果及记录。
- 确认绑定企业、操作者、动作、确切对象、内容和版本；批量冻结记录集合，不重新搜索扩大。业务确认默认十分钟，内容/权限/版本变化重确认。
- 服务端显式拒绝无字段权限的变更（Frappe 可能静默恢复字段），执行后核对实际差异；HTTP 成功不等于成功。原生手工按钮不叠加 Agent 确认。

## 阶段三：应用配置、预览与发布

- 生成原生配置实现字段、布局、保存及工作流，不生成任意代码。仅新应用和非破坏扩展，禁止删除/重命名既有字段、类型变化、隐式回填、覆盖既有 ERP 工作流。
- 沿用原生配置权限，不新增发布角色、不允许 Agent 提权。
- 隔离预览 Site 使用合成数据，禁止邮件/Webhook 等外部副作用；预览应用与目标发布分别确认。
- 发布绑定不可变配置包、目标及基线，默认三十分钟；自定义 App 钩子协调 Agent 与原生配置并发修改。
- 逐步记录结果；DDL 可能自提交，不承诺整体回滚；部分成功/结果不明停止核对，不整包重跑。

## 阶段四：日常使用及兼容

- 日常企业 Site 无合成数据，真实企业初始化由用户填写；首次真实数据使用前备份及隔离恢复验证。
- 沿用总约 4 GiB/2 CPU 授权，先核对常驻约 3712 MiB/1.9 CPU 与单 Agent 384 MiB/0.1 CPU；控制 Agent/预览并发。资源不足申请授权，不降低隔离、不默认加常驻服务。
- alpha/beta 保留合成验收；正式入口指向企业 Desk，平台首页不承担业务工作台。保留现有浏览器登录，不随意退出/关闭。

## 验收矩阵

- UI：列表/表单/子表/筛选/选中项；切页不串对象、不覆盖未保存内容。
- 会话：跨进程、多标签、刷新、断线、取消、压缩、配置版本变化；无重复执行/跨企业串话。
- 权限：只读禁止写、字段权限、撤权历史摘要、伪造上下文及工具请求。
- HITL：未确认零写；修改后重确认；过期/重复/并发/响应丢失/部分成功都有真实记录。
- 发布：隔离预览、原生保存工作流、并发配置、部分失败与结果核实。
- 真实固定版 DSH 插件、真实模型、真实 Frappe 权限和页面分别验证，替身不可替代。
