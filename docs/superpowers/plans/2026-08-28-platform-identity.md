# 阶段 3：已确认的平台身份拓扑实施

用户已确认：独立 Frappe 平台 Site 管理统一登录、跨企业成员关系；业务 Site 保留各自业务权限。

## 实施顺序

1. 独立平台与第二业务 Site，单独站点卷和数据库用户，不修改上游核心。既有 alpha 站点与回归保持可用。总资源不超 4 GiB / 2 CPU。
2. 平台自定义 App 保存 Enterprise / Membership。平台身份来自原生 Frappe session；普通用户只能查询自己的成员关系，平台管理员单独维护绑定。
3. 企业读请求通过平台服务端解析固定站点与该成员专用普通用户凭证；先验证成员启用、企业可用、身份匹配，再由 ERP 再查权限。浏览器与模型均不取得 API 密钥。不是按同邮箱自动授权。
4. 前端真实账号与企业选择、记录与字段读取取代对应演示页面；未接入构建发布不显示为正式可用。
5. DSH 只读任务接入、任务归属与持续复查、第二企业交叉访问、UI 与真实模型分别验收。真实模型费用超出既有单次验证授权前须单独确认。

统一登录首先为平台入口登录；原生业务 Desk 的跨 Site 单点登录需另外核验 Frappe OAuth 回调与成员撤销，不把服务器用户专用凭证代理等同于跨站浏览器 SSO。

## 验证

先失败后实现：Guest、无成员、停用成员、不可用企业、绑定身份不符、越权字段/记录、跨企业凭证与任务、直接请求与切换后缓存。真实调用不以 UI 隐藏或纯函数测试替代。分类提交，不推送。
