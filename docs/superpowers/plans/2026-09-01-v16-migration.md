## 上下文

项目当前锁定 ERPNext `v15.119.3` / Frappe `v15.118.0`(镜像 digest `sha256:cf5905…d341`),已在本地合成环境完成制造闭环(alpha 分段 + daily 端到端)验证,尚无生产租户。经裁决(2026-09-01):升级 v16 立项,理由是迁移成本单调性 —— 现在无租户数据,换基线 = 换 digest + 重跑验证;上线后成本按租户站点数线性增长且不可逆。v16 制造侧收益(MRP、委外流程重做、工单库存预留、批次追溯、委外落地成本)正打在项目主战场(7 条 make 路由中 4 条为委外)。

用户指令:彻底完整迁移到 v16,处理已有代码,完成并通过后移除原 v15。

## 目标与非目标

**目标**
- 四站点(validation/platform/beta/daily)全部在 v16 上 fresh provision 重建并通过全量验证(251 Python + ~160 前端 + 集成 + 制造闭环端到端 + HITL 人工验收)。
- 处理全部 v16 适配点(见风险清单),含 v16 推荐的顺势项(DocType sort_field 显式化、add_to_apps_screen)。
- 终验通过后移除 v15:卷/镜像/digest 硬编码/文档降级为历史。

**非目标**
- 不动宿主 `.venv`(Python 3.12.11)、DSH SDK/Runtime `0.1.1rc1`、MCP SDK 1.26.0 及 requirements.lock(除非探针证明必须)。
- 不做 bench migrate 数据迁移(全部合成数据,fresh provision)。
- 不引入浏览器自动化基建(UI 继续人工验收落档)。
- 不 fork/patch Frappe、ERPNext 核心(AGENTS.md 约定;若探针发现必须 patch,回到用户重新裁决)。
- 不采用 frappe-mcp(已裁决,与本迁移正交)。

## 已核验关键事实(2026-09-01,来源:仓库探索 + 上游源码比对)

### 环境基线
- 单 compose `infra/compose.validation.yml`,project `dsherp-validation`,10 个 frappe/erpnext 服务全钉同一 v15 digest;4 站点 3 bench 卷(validation 18081/18082、platform 18083、beta 18084/18085、daily 18086);MariaDB 10.6 / Redis 6.2 独立钉 digest;网络 `validation`(internal)+`api`。

## 迁移策略

- **fresh provision,不 bench migrate**:v16 用新命名卷重建四站,v15 卷保留为回退,终验通过后移除。
- **双轨不并行运行**:停 v15 栈(不删卷)→ 切 compose 到 v16(新卷名)→ provision → 验证;端口复用不冲突(v15 已停)。
- **检查点协作**:C1 探针、C2 代码适配、C3 四站重建+回归、C4 端到端终验、C5 文档+移除 v15。每个检查点 Claude 审计放行。

## 关键时序约束(审查发现的缺环,已并入下面各阶段)

- 探针必须用**独立 throwaway compose project**(不同 project 名+临时端口+临时卷,用后即焚);v15 project 独占 `dsherp-validation` 名与 18081-18086 端口,严禁在现有 project 上换镜像 up(会写坏 v15 sites 卷)。
- **v15 停机在阶段 3 开头**(端口/容器名复用要求 v16 up 前 v15 `down` 不带 `-v`);阶段 5 只做卷/镜像/文档移除。C3 起回退 = 回滚 digest commit + `docker compose up`。
- **dist 重建时点**:`.gitignore` 全局忽略 `dist/`,无脚本自动构建;C2→C3 之间必须显式"宿主重建 dist + sha256 落档",否则 /desk 前端改造在容器内不可见且无报错。
- **指纹盲区**:`runtime-files.json` 不含 compose/runtime_host.py/prepare_agent_runtime.sh/前端文件 —— digest 翻转不作废在飞 run。阶段 2 扩指纹清单(推荐)。
- **宿主 worker 停启序**:C2 过 → 停宿主 agent-worker → v15 down → v16 up + fresh provision → `.runtime/` 凭证全量再生 → worker 用新凭证重启。
- **agent-runtime 卷**:v16 用新卷名;改 `runtime_host.py:8` 常量 ≠ 卷已重建,重建是阶段 3 显式步骤。
- **daily cron/备份**:scheduler 在 `profiles: [scheduled]`、daily provision/备份验证在 `profiles: [control]`,默认 up 不含;阶段 3/4 显式带 profile 拉起并跑 `verify_daily_backup.py`。
- **legacy profile 裁决**:websocket/worker 服务(`profiles: [legacy]`,command 硬引用 `apps/frappe/socketio.js`)在阶段 2 定保留/更名/删除,否则阶段 5 清理无依据。
- **探针脚本是 repo 内可重复资产**:C1 结论测于空 probe 站,C2 完成后必须在 probe 环境**复跑**全部探针(commit no-op 等只有容器内可复现)。
